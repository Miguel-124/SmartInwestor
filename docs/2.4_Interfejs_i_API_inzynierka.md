# 2.4. Projekt interfejsu użytkownika i specyfikacja API

Ponieważ sercem systemu jest Backend (Django REST Framework), kluczowym elementem projektu jest specyfikacja punktów końcowych (endpoints), które udostępniają funkcjonalności dla frontendu (React) oraz aplikacji mobilnej.

## Specyfikacja kluczowych punktów końcowych (API)

Wszystkie endpointy (poza logowaniem i rejestracją) wymagają autoryzacji nagłówkiem: `Authorization: Bearer <access_token>` (JWT).

### Auth (`/api/auth/`)

Obsługa rejestracji, logowania (w tym przez Google), wydawania i odświeżania tokenów JWT oraz zarządzania kontem:

| Metoda | Endpoint | Opis |
|--------|----------|------|
| POST | `/api/auth/register/` | Rejestracja (email, hasło). |
| POST | `/api/auth/login/` | Logowanie (email, hasło) – zwraca `access`, `refresh`, `user`. |
| POST | `/api/auth/google/` | Logowanie przez Google – body: `{ "id_token": "..." }`. |
| POST | `/api/auth/token/refresh/` | Odświeżenie tokenu – body: `{ "refresh": "..." }`. |
| GET | `/api/auth/me/` | Dane zalogowanego użytkownika. |
| POST | `/api/auth/logout/` | Wylogowanie (opcjonalnie blacklista refresh tokena). |
| POST | `/api/auth/set-password/` | Ustawienie hasła (np. po rejestracji przez Google). |
| POST | `/api/auth/change-password/` | Zmiana hasła. |

### Portfele (`/api/portfolios/`)

CRUD portfeli użytkownika. Portfel systemowy „Main” zawiera wszystkie transakcje i nie może być usunięty.

| Metoda | Endpoint | Opis |
|--------|----------|------|
| GET | `/api/portfolios/` | Lista portfeli (z polem `is_main`). |
| POST | `/api/portfolios/` | Utworzenie portfela – body: `{ "name": "..." }`. |
| GET | `/api/portfolios/{id}/` | Szczegóły portfela (nazwa, pozycje, `is_main`). |
| PATCH/PUT | `/api/portfolios/{id}/` | Aktualizacja portfela. |
| DELETE | `/api/portfolios/{id}/` | Usunięcie portfela (zablokowane dla Main). |
| GET | `/api/portfolios/{id}/positions/` | Lista pozycji (symbol, quantity, total_cost, avg_price). |
| GET | `/api/portfolios/{id}/transactions/` | Lista transakcji w portfelu. |

### Transakcje (`/api/transactions/`)

Dodawanie i przeglądanie transakcji z przypisaniem do portfeli (M2M). Portfel „Main” jest dodawany automatycznie.

| Metoda | Endpoint | Opis |
|--------|----------|------|
| GET | `/api/transactions/` | Lista transakcji (opcjonalnie: `?portfolio=<id>`, `?symbol=`, `?side=BUY|SELL`). |
| POST | `/api/transactions/` | Dodanie transakcji – body: symbol, side, quantity, price, fee, executed_at, asset_type, portfolio_ids. |
| GET | `/api/transactions/{id}/` | Szczegóły transakcji. |
| PATCH/PUT | `/api/transactions/{id}/` | Aktualizacja transakcji. |
| DELETE | `/api/transactions/{id}/` | Usunięcie transakcji. |
| GET | `/api/transactions/symbols/` | Lista unikalnych symboli użytkownika (np. do filtrów). |

### Ceny i analityka (`/api/prices/`)

Pobieranie kursów (CoinGecko), wykresów oraz wskaźników technicznych i sentymentu z internetu.

| Metoda | Endpoint | Opis |
|--------|----------|------|
| GET | `/api/prices/quote` | Kursy – parametry: `symbols=BTC,ETH`, `vs=usd,pln`. |
| GET | `/api/prices/chart` | Dane do wykresu – parametry: `symbol`, `vs`, `days`. |
| GET | `/api/prices/indicators` | Wskaźniki EMA, RSI i sygnały przecięcia EMA – parametry: `symbol`, `vs`, `days`, opcjonalnie `ema_fast`, `ema_slow`, `rsi_period`. Zwraca: times, prices, ema_fast, ema_slow, rsi, signals. |
| GET | `/api/prices/sentiment` | Analiza sentymentu na podstawie nagłówków z wyszukiwarki (Google News) – parametr: `symbol`. Zwraca: sentiment_score, sentiment_label, headlines, summary. |

### Asystent AI (`/api/ai/`)

| Metoda | Endpoint | Opis |
|--------|----------|------|
| POST | `/api/ai/chat/` | Wysłanie pytania do wirtualnego doradcy – body: `{ "query": "..." }`. Backend buduje kontekst i zwraca odpowiedź wygenerowaną przez model AI (np. Google Gemini). Zwraca: `{ "response": "..." }`. |

## Koncepcja wizualna (UI)

Interfejs graficzny (React, Vite) został zaprojektowany w stylu panelu inwestora z ciemnym motywem (tło #121212, akcenty cyan/zielony).

### Ekran logowania i rejestracji

- Formularz logowania / rejestracji (email, hasło).
- Przycisk „Zaloguj przez Google” (OAuth 2.0, Client ID z zmiennej środowiskowej).
- Przełącznik między trybem logowania a rejestracji.

### Panel główny (po zalogowaniu)

- **Lista portfeli** – nazwa, oznaczenie portfela „Main” (wszystkie transakcje), przycisk Usuń (niedostępny dla Main). Klik w portfel otwiera szczegóły.
- **Szczegóły portfela** – podsumowanie pozycji (symbol, ilość, średnia cena, łączny koszt) oraz lista transakcji w tym portfelu.
- **Dodawanie transakcji** – typ aktywa (akcje/ETF lub krypto), wyszukiwanie symbolu (z opóźnieniem, integracja z zewnętrznym API), auto-uzupełnienie ceny, ilość, cena, data, przypisanie do portfeli (checkboxy). Walidacja i komunikaty błędów z backendu.
- **Analiza techniczna (EMA, RSI)** – wybór symbolu i okresu (1–90 dni), przycisk „Pobierz wskaźniki”. Po pobraniu: wykres ceny z liniami EMA (szybka/wolna), osobny wykres RSI z zaznaczonymi strefami wykupienia i wyprzedania, ostatni sygnał kupna/sprzedaży.
- **Sentyment z internetu** – wybór symbolu, przycisk „Pobierz sentyment”. Wyświetlanie etykiety (pozytywny/negatywny/neutralny), score, podsumowania oraz rozwijanej listy nagłówków z wyszukiwarki z oceną sentymentu.

### Widget AI (czat)

- Stały przycisk (FAB) w prawym dolnym rogu – otwiera okno czatu.
- Okno czatu z historią wiadomości i polem wpisywania pytania.
- Wysyłka zapytania do `/api/ai/chat/` i wyświetlanie odpowiedzi wirtualnego analityka.
